## 用法

这一页是底座。写任何文档先满足六条原则。句子层面的执行细则见[写作与整理规范](/meta/conventions)第 9 节。

两者冲突时，按用户、事实、语气、形式的顺序取舍。

## 依据与强度

这六条原则没有单一母本。它们的共同点能在三份规范里找到，三份都逐字读过：

- ISO 24495-1:2023《Plain language，简明语言》，国际标准。
- GOV.UK 写作指南，英国政府。
- 《Federal Plain Language Guidelines》（2011），美国政府。

三份都是规范文件，不是对照实验。多来源一致，只能说明写作规范有共识，标 `[中]`。

阿里那份 Style Guide（2018，EN→ID，VER 1.0）只作旁证。它面向印尼语本地化，公开形态是图书预览页的前几页。本库采用它组织条目的形状，不把它当依据。

原文和逐字引语见[证据页](/meta/evidence)第 2 节。

## 六条原则

每条只给一句主张。来源列写它落在哪份规范里；没有规范可落的，先算本库约定。

| # | 原则 | 来源 | 证据 |
|---|---|---|---|
| 1 | 用户优先。先写结论；难词先解释；删掉读者不需要的信息。 | ISO 的读者可用性；GOV.UK 的用户需求优先 | `[中]` |
| 2 | 先认文档类型和受众。笔记、规范、分析文各有结构。 | GOV.UK 的受众判断；ISO 的适用性 | `[中]` |
| 3 | 一句一个主张。主谓齐全；一句不塞两个判断。 | ISO 5.2.2；美国指南 §III.b.1 | `[中]` |
| 4 | 术语一致。同一个人、同一件事，全文一个说法。 | 华为《OpenHarmony 开发者文档风格指南》 | `[中]` |
| 5 | 译意不译词。引语逐字；转述写「据……」；不逐词硬译。 | 翻译实践约定 | `[约定]` |
| 6 | 资料可核验。先查原文；找不到标「未核验」；不编造。 | 本库约定，见第 9 节 | `[约定]` |

第 5 条和第 6 条没有对应规范，这是它们标 `[约定]` 的原因。
第 4 条的术语一致，下文「用词」一节还有一层：统一说法之外，还要查表定译名。

## 语气

- 直接、清楚、可读。不端着，不堆术语。
- 不写翻译腔：长定语、名词化、一长串连续被动。
  单个被动不在此列。结果比执行者重要时，被动更准确。
- 原文啰嗦可以压缩。事实、数字、引语不改。
- 语气随文档类型变：笔记简短，规范精确，分析文密集。

## 术语

查找顺序：

1. 查[术语与译名表](/meta/glossary)。
2. 查术语在线或国标。
3. 查 Microsoft 语言门户（中文）。
4. 查已出版的中文技术书和官方文档。
5. 以上都没有，标「本库约定」，并在表里新增一行。

语境优先于词表。表里没有、语境特殊的，先按语境写，再补表。

译名不改口，但表要跟着用。笔记里出现表外的新词，写完整篇后再回表里补一行，别等到下一篇文章重新起名。

## 中文细则

### 称呼

- 对读者用「你」，对自己用「我」。
- 「我们」第一次出现时说明指谁。
- 全文只用一个称呼，不混用「你」「您」「开发者」。

### 用词

- 术语、缩略语、同一对象全文只用一个说法，不中英混用。
- 行业通用术语先随国标，再随本库表。
- 不随意缩写英文，不自创缩略语。
- 术语首次出现写成「中文（English，缩写）」。
- 行话、成语先过「能不能译」这一关；译不出，换成具体说法。

常用词：

| 用 | 不用 |
|---|---|
| 登录 | 登陆 |
| 单击 | 点击 |
| 图像 | 图象 |
| 计费 | 记费 |
| 阈值 | 阀值 |
| 重写 | 复写 |
| 命令 | 指令 |
| 外形 | 外型 |

### 句段

- 一句一个主张。读完要回头，就拆。
- 一句话里逗号连成串，通常说明它塞了两个主张。先拆，数逗号不是目的。
- 不用双重否定。
- 能量化就量化：「文件大于 16MB」，不写「文件超限」。
- 段首给结论，一段一件事。

## 不采用

- 印尼语敬语与正式度分级。
- 对读者称「开发者」。
- 句长、逗号数的硬阈值。
- 「不是 X，而是 Y」的对偶。
