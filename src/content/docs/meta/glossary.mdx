## 用法

写之前先查表。表里没有的，按下文「查找顺序」判断。

首次出现写成「中文（English）」或「English（中文解释）」，之后全文只用一个形式。

用户指定的译名优先于通行译法。表里标「用户指定」的行不自行改回。

## 查找顺序

| 步 | 查什么 | 命中后 |
|---|---|---|
| 1 | 「不译」表 | 直接用英文，首次补一句解释 |
| 2 | 「译」表 | 用中文，首次中英并列 |
| 3 | 都没有 | 查术语在线或国标；仍无，保留英文并标「本库约定」 |

表里没有、语境特殊的，先按语境写，写完再回表里补一行。

## 分类规则

| 类别 | 处理 | 例子 |
|---|---|---|
| 产品名、仓库名、文件名、命令、代码标识符 | 不译 | `poteto-mode`、`GLOSSARY.md`、`npx skills add` |
| AI 生态词 | 不译 | Agent、subagent、harness |
| 行业里以英文为主的流程名 | 不译，首次加一句解释 | skill、playbook |
| 中文有稳定译法的通用概念 | 译 | feedback loop → 反馈循环 |
| 多种译名、容易误解的概念 | 按用户指定，首次中英并列 | deep module → 深度复杂模块 |

## 不译

| English | 说明 | 来源 |
|---|---|---|
| Agent | AI 执行者；指具体产品时按官方写法 | 通行 |
| subagent | 「子代理」只用于解释 | 通行 |
| harness | agent harness 的简称；首次可注「Agent 运行环境」 | 通行 |
| worktree | git worktree 的专名 | 通行 |
| skill / skills | 指 SKILL.md、skills CLI 或技能包 | 通行 |
| playbook | 首次写「playbook（预设流程）」 | 通行 |
| PR | pull request | 通行 |
| TODO | 代码与任务项 | 通行 |
| brief | 交给 subagent 的任务简述；首次写「brief（任务简报）」 | 本库 |
| owner | 一处代码或一个 PR 的唯一负责人 | 本库 |
| initializer | 初始化脚本；不译 | 本库 |
| `poteto-mode`、`comment-sicko`、`grilling`、`tdd` | 技能名与标识符 | 通行 |

## 本库约定

表里没有通行译法、由本库定的词。

| English | 中文 | 说明 |
|---|---|---|
| grilling | 拷问 | 技能名 `grilling` 保留英文 |
| verdict | 判定 | 指 PR 的结论档位时用 |
| blocking edge | 阻塞边 | 尚未在笔记里启用 |
| context pointer | 上下文指针 | 通行中文，本库采用 |
| context load | 上下文负载 | 尚未在笔记里启用 |
| deletion test | 删除测试 | 通行中文，本库定名 |
| instrumentation | 插桩 | 首次写「instrumentation（插桩，在运行中取样）」 |

标「尚未在笔记里启用」的词，是给以后留的位置。用上时把标记删掉。

## 依据

译名有三个来源，按优先级排：

1. 用户指定。能覆盖通行译法，且不自行改回。
2. 通行译法。以国标、术语在线、已出版技术书为准。
3. 本库约定。前两者都没有时自定，写进本表。

要替换用户指定的词，先问一句，得到新写法后再改表和正文。
